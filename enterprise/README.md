This directory holds Slatebox's enterprise features. They run on [Slatebox Cloud](https://app.slatebox.com), and on a self-hosted install once a license key from Slatebox LLC unlocks them ("Upgrade on prem"). It is **not MIT licensed**. Everything outside this directory is MIT ([LICENSE](../LICENSE)).

## What lives here

Outside agent connections: Slatebox as an MCP *client*.

- Inviting an outside MCP server onto a slate as a named cursor, from the gallery or a pasted address.
- Its suggestions, shown live on the slate as ghost notes that anyone can Keep or Discard.
- Connectors and the integrations built on them, with their OAuth sign-in (callback `/connectors/oauth/callback`).
- Agents read and write: a change the person asks for lands as an action card a person approves (see below).

### What is built (S2a: open servers)

- `server/mcp-fetch.mjs`: the only network path (https only, every resolved address public, redirects re-checked, size and time caps, a real User-Agent, no listening stream).
- `server/mcp-session.mjs`: one short `@modelcontextprotocol/client` session per job (2026 servers through `server/discover`, older ones through `initialize`). A signed-in server gets the asking person's token, bound to that server's origin only.
- `server/tools.mjs`, `results.mjs`, `context.mjs`, `translate.mjs`: consent to tool hashes, quarantine of results, the context packer ("what leaves Slatebox"), and the two-step translator (plan lookups, then lay out notes; its words live in the prompt registry, `connectors.*`).
- `server/recipes.mjs`, `excalidraw.mjs`: exactly what was asked (the request's number of notes, one answer per ask, read-me tools never offered), each gallery agent's known asks as fixed steps, and Excalidraw elements drawn by a fixed recipe (shared with Import from Excalidraw).
- `server/gallery-admin.mjs`: the gallery as data in /admin/ai › Agent gallery (aiAgents, audited, people only).
- `server/service.mjs`, `actions.mjs`, `meteor.js`: `connectors.list/discover/connect/disconnect/call`, each a Meteor method, `/api/v1` route, exec call and MCP tool. On Cloud the inviter needs Pro; only the inviter asks; any editor keeps its notes (only the inviter approves its changes elsewhere, unless they let editors).
- `client/`: "+ Invite agent", the walkthrough, each invited agent's chip on the people strip (ask it there, or by `@name` in Ask Slatebox) and the live ghosts on the canvas with Keep and Discard on each.
- Tests: `npm run test:enterprise` (with the hostile server in `scripts/mcp-test-servers.mjs`).

### What is built (S2b: servers that need sign-in)

- `server/oauth.mjs`: the OAuth steps and their checks: protected resource metadata (its `resource` must be the invited server), authorization server metadata (its `issuer` must match exactly), PKCE S256 required, every endpoint https and public, registration in order (an app registered ahead of time, Slatebox's Client ID Metadata Document at `/oauth/mcp-client.json`, automatic registration, a pasted client id), `resource` on every request, `iss` checked on the callback.
- `server/signin.mjs` and `server/routes.mjs`: the popup flow. `POST /connectors/oauth/start` (from the signed-in Slatebox page, with its login token) lets only the flow's owner claim it, ties it to the browser (HttpOnly cookie) and answers the server's sign-in address for the popup; there is no GET start, so a link can never start someone's sign-in; `GET /connectors/oauth/callback` takes the single-use state, checks the browser and `iss`, and exchanges the code. Flows expire after 10 minutes.
- `server/credentials.mjs`: the vault. Tokens, pasted keys and registration secrets are sealed (AES-256-GCM, `web/app/server/metering/vault.mjs`) under the app's existing `SLATEBOX_KEY_ENCRYPTION_KEY`, bound to person, address, issuer and field. Refresh runs under a lease; a refused refresh shows "needs sign-in" on the agent. Removing the last agent on a server revokes and forgets its sign-in.
- `connectors.signIn`, `connectors.signInStatus`, `connectors.useKey` (pasted keys and tokens, `writeOnly`): Meteor method, `/api/v1` route, exec call and MCP tool, like the others.
- Settings (`server/connector-settings.mjs`): `settings.connectors.oauthApps.<provider>.{clientId, clientSecret, scopes?}`. GitHub is a known provider (issuer `https://github.com/login/oauth`, scopes `public_repo read:org` unless `scopes` widens them, pinned to `https://api.githubcopilot.com`); any other provider also gives `issuer` and `resources`.

### What is built (agents read and write, 2026-11-24)

- `server/tools.mjs`: `classifyTool` (a destructive name or `destructiveHint` first; `readOnlyHint` never makes a name that writes a lookup; then the name; the gallery recipe's `tools` word wins at consent). `reconcile` answers `allowed` (lookups, run during an ask) and `writable` (changes, only ever proposed), never looser than the stored consent. `destructiveArgs`: an update that closes, cancels, archives or merges is destructive. `changeClauses` / `asksForChange`: a change is planned only when a clause of the person's own words starts with a verb of change and names a thing an allowed tool makes ("list the open issues" never does).
- `server/translate.mjs`: `writePlanPrompt` / `checkWrites`, the change planner (prompt `connectors.plan.writes`), capped like lookups; a recipe's fixed values (`"method": "create"`) win over the planner's.
- `server/outside.mjs`: action cards. Their words (label, title, body, where, item, and every other argument in `more`), built from typed arguments, in full (`fitsOnCard`: one that does not fit is never proposed); `publicCard.args` is exactly what approving sends; the done link (a checked https link from the answer, never one the change's own arguments carried) and plain failure words. States: waiting, running (a lease of `CARD_LIMITS.runningMs`), done, failed (refused before anything was made: Approve tries again), unclear (sent, no answer: never re-sent by Approve; Try again anyway on the card or the chip is `connectors.approve` with `again: true`, a person only), declined. Each placed card's ghost is marked (`suggestions.retext` with `card: { id, state }`), so the canvas draws Approve and Decline on it (Approve and Decline are Keep and Discard of that note alone).
- `server/service.mjs`: cards in the answer (one more group of notes in the same suggestion); `approve` (the tool checked again against the consented hash, then called once, as the inviter; claimed once), `decline`, `gate` (the app's `suggestions.decide` asks it first: Keep on a card alone approves it, Keep all holds cards, Discard declines, Undo leaves done cards and says so), `setActing` / `integrationSetActing` (act without asking, who approves: wider only by the inviter; audited; kept in the agent's activity), `outsideList`.
- `common/gallery.mjs`: Linear at its full address (the read-only one is an alias; `writesAddress` names the full one for an integration still at the alias, and `integrations.connect` with `replaces` moves it there; `RETIRED_WORDS` keeps an old "Reads only." default from being served as an edit), write recipes for Linear (create issue, comment, update status) and GitHub (open issue, comment, open a pull request from an existing branch), `tools` corrections (GitHub's merge and file writes are destructive). `integrations.allowChanges` turns on the non-destructive changes an earlier consent left off, on every slate (person only). `common/integration-words.mjs`: the gallery's ✓ Connected line and next step, and the Integrations page's one-line tool summary.
- Actions: `connectors.outsideActions` (`list_agent_changes`), `connectors.approve` (`approve_agent_change`; a token only for an agent that acts without asking, never destructive), `connectors.decline` (`decline_agent_change`), and the person-only `connectors.setActing`, `integrations.setActing`.
- Tests: `scripts/agents-read-write.test.mjs` (in `npm run test:enterprise`) and the gate in `scripts/agent-suggestions.test.mjs`.

### What is built (team addresses, Slatebox Cloud only, 2026-11-24)

A free `https://<name>.slatebox.team` for a self-hosted Slatebox (`npx slatebox install`): Slatebox Cloud makes a Cloudflare Tunnel and a proxied CNAME in Slatebox's own Cloudflare account and gives the install that tunnel's connector token; `cloudflared` in the install connects outbound, so nobody sets up DNS, ports or certificates.

- `team-addresses/names.mjs`, `blocked.mjs`: one DNS label (3–32, a–z 0–9 hyphens, no `--`, so no punycode), reserved names, brand and offensive words with look-alike digits folded, and the administrators' runtime blocklist. Reserved, blocked, taken and held names all answer "unavailable".
- `team-addresses/cf.mjs`: the only Cloudflare calls (injected fetch; 10 s timeout; 4 attempts with backoff on network errors, 429 and 5xx only; only `errors[].code`/`message` kept).
- `team-addresses/claims.mjs`: the claim service. Create is an idempotent saga (tunnel `sbx-<claim id>`, ingress to the constant origin `http://localhost:7070` with a 404 catch-all and private routing off, CNAME, then the connector token, then the install credential) that a replay resumes and a hard failure undoes in reverse. 3 addresses per account, 5 new a day, 20 in 30 days, 3 renames in 30 days, 12 token fetches an hour per address, a tunnel cap (800) and a circuit breaker (more than 50 claims an hour pauses new claims). Released and renamed names are held for their owner for 30 days; a takedown holds the name from everyone for a year. Connector tokens are never stored; install credentials (`sbxi_…`) only as their SHA-256. Every step is audited without secrets.
- `team-addresses/reconcile.mjs`: every 10 minutes on one server (a lease): finishes releases and cleanups, records status from Cloudflare, tells owners when two connectors serve one address, repairs ingress and records, deletes orphans, reaps names that never connected within 24 hours or sat idle 90 days (told at 60), and checks the zone's settings.
- `team-addresses/routes.mjs`: `/api/v1/team-addresses` (availability, claim, list, rename, release, install-credential; `/self`, `/self/connector-token`, `/self/rename-complete`, `DELETE /self` for the install). Plain routes, never actions, so no token reaches an MCP tool or exec. User routes take the device-code token from `/oauth/device_authorization` (`web/app/server/oauth/device.mjs`, scope `team-addresses`, 15 minutes, bound to this resource).
- `team-addresses/admin.mjs`, `client/TeamAddressesAdmin.jsx`: Admin tools › Team addresses: search, suspend (451 at the edge within seconds), unsuspend, release with a one-year hold, pause new claims, why a name is unavailable, the audit.
- Gating: registered wherever enterprise code runs, but every route and method answers 404 unless this server is Slatebox Cloud by its signed key (`cloudLicensed`, checked on every call) and `settings.cloudflare.teamClaims` is set; nothing starts on a licensed on-prem install.
- Tests: `scripts/team-addresses.test.mjs` (in `npm run test:enterprise`, against the fake Cloudflare in `scripts/fake-cloudflare.mjs`) and `scripts/oauth-device.test.mjs`.

Slatebox as an MCP *server* (`/mcp`, the CLI, `/api/v1`) is not here. It is MIT and works on every install.

## Where it runs

- **Slatebox Cloud.** `settings.public.edition` is `'cloud'`. Inviting agents needs Slatebox Pro for the person who invites.
- **Self-hosted, locked.** Every self-host image carries this directory. It stays locked: the app never requires it and nothing registers.
- **Self-hosted, unlocked.** A license key from Slatebox LLC (`settings.enterprise.license`, `settings.enterprise.licenseFile`, or the `SLATEBOX_LICENSE` / `SLATEBOX_LICENSE_FILE` environment variables) unlocks it on that install. `web/app/server/enterprise-license.mjs` checks the key offline: an Ed25519 signature against Slatebox LLC's public keys, which are in that file; the private keys never are. The key may name the install's host names, and ends on its date after a 14-day grace. A licensed install has no Slatebox Pro, so its license is what lets people who can edit invite agents. Every action, method and route is checked against the license again while the server runs. Administrators see the state, and **Upgrade on prem**, in Admin tools (`enterprise.licenseStatus`).
- **No feature switch.** Wherever this code runs, invited agents are on. `settings.connectors.off: true` (server-side, never public) is the kill switch.
- **Not enterprise.** Single sign-on with the bundled Keycloak is MIT and free on every install, as are Slatebox's own MCP server, CLI and API.
- **Loading.** Where enterprise code is locked the app never requires it. Where it is unlocked, `web/app/server/enterprise-loader.mjs` calls `server/index.js` → `register(api, context)` once at start, and writes `settings.public.enterprise` so browsers know; `web/app/client/enterprise.js` then loads `client/index.jsx` as its own chunk. This code reaches the app only through that `api`: actions (each one a Meteor method, an `/api/v1` route, an exec call and an MCP tool, with the same permission checks), routes, methods and UI slots.
- **Builds.** Meteor builds only `web/app`. Run `node scripts/enterprise-stage.mjs link` in local development, which makes the git-ignored link `web/app/enterprise` → `enterprise/`. Every image build copies this directory into its build context and checks it is there (`scripts/test-port-container.mjs`, `self-host/build-images.sh`, `enterprise-stage.mjs check-present`).
